# 深入调查：调研循环与证据设计

> 供产品实现与 AI 协作者阅读。当前代码仍为 MVP（观察名单 + 调查中状态）；**本节为 Phase 2 目标形态**。

---

## 1. 设计目标

1. **AI 执行检索与初筛，人类负责质疑与定稿**——避免 AI 讨好、避免无引用结论。
2. **Loop 而非流水线**：每一轮「收集 → 提炼 → 推敲 → 沉淀」，证据经得起反复逻辑检验。
3. **只存关键信息 + 引用地址**，不 hoard 全文；可追溯、可推翻、可修订。
4. **优质信源可积累**：人类（或 AI 建议经人类确认）把高质量网址记入「信源库」，下次同类调查复用。

---

## 2. 五阶段 Tab（调查中详情页）

| Tab | 名称 | 本阶段要回答什么 | 阶段过关条件（示意） |
|-----|------|------------------|----------------------|
| 1 | 坐标系 | 卖什么、卖给谁、行业角色 | ≥3 条有引用的业务事实 + 1 张业务地图草稿 |
| 2 | 机理 | 供需与利润从哪来、对什么敏感 | 利润拆解 + 1 条利润敏感因子（有引用） |
| 3 | 约束 | **关键限制因素**与发展因素候选 | 1 条生死线假设 + 代理指标 + 证伪条件 |
| 4 | 系统 | 上下游、竞争、政策与治理 | 价值链草图 + 外部依赖清单 |
| 5 | 总结 | 本质总结与跟踪项 | 成稿区分【事实/推断/未知】+ 跟踪清单 |

每 Tab 内嵌 **调研循环**（见 §3），可跑多轮直到研究员认为「本阶段够了」再点「进入下一阶段」。

### 各 Tab 引导问题（给 AI / 人类）

**Tab1 坐标系**
- 收入从哪些产品线/地区来？各占多少？（引用）
- 客户是谁（ToB/ToC/政府）？行业处在产业链哪一段？
- 和 2 家可比公司比，结构差异在哪？

**Tab2 机理**
- 量、价、成本、费用里，谁驱动了最近一期利润变化？
- 需求是行业 β 还是公司 α？有无替代威胁？
- 毛利率变化是结构还是一次性？

**Tab3 约束**（Tesseract 核心）
- 当前阶段**唯一**最关键的限制是什么？（候选 ≤3，最终聚焦 1）
- 用什么**可观察代理指标**验证？数据从哪来？
- 若限制缓解，**发展因素**是什么？需要什么领先信号？

**Tab4 系统**
- 上游谁有定价权？下游谁掌控渠道？客户集中度？
- 政策/监管/地缘：顺风还是逆风？是否可持续？
- 股权与激励：是否与小股东利益一致？

**Tab5 总结**
- 用一段话写本质（标注事实 vs 推断）
- 12–24 个月：限制可能缓解吗？依赖什么？
- 仍无法回答的 3 个问题是什么？

## 3. 调研循环（单阶段内的 Loop）

每一轮循环固定四步，UI 上呈现为时间线或卡片栈：

```
┌─────────────────────────────────────────────────────────┐
│ ① 定向 (Orient)    本轮要验证什么？与哪条假设相关？        │
├─────────────────────────────────────────────────────────┤
│ ② 收集 (Collect)   AI 检索/建议 URL；人类粘贴或确认抓取   │
├─────────────────────────────────────────────────────────┤
│ ③ 推敲 (Challenge) 交叉验证、反证、标【事实/推断/未知】    │
├─────────────────────────────────────────────────────────┤
│ ④ 沉淀 (Commit)    写入证据卡片（摘要 + citations）       │
└─────────────────────────────────────────────────────────┘
         │                                    │
         └──────── 未过关 / 发现矛盾 ──────────┘
```

### ③ 推敲 — 过关清单（逻辑经得起反复问）

沉淀前必须自检（AI 辅助提问，人类确认）：

| 检查项 | 说明 |
|--------|------|
| 有引用 | 每条【事实】至少 1 个 citation；无来源则标【未知】 |
| 可证伪 | 写清「若出现 X，则本假设不成立」 |
| 无跳跃 | 结论是否由事实经机制推导，而非叙事联想 |
| 无讨好 | AI 必须提出 ≥1 条反证或替代解释 |
| 可修订 | 新证据可 `supersedes` 旧卡片，保留历史 |

未通过则回到 ② 或 ①，**不强行 Commit**。

## 4. 数据模型（IndexedDB，Phase 2）

### 4.1 `evidence` — 证据卡片（沉淀产物）

| 字段 | 说明 |
|------|------|
| id | 主键 |
| companyId | 关联公司 |
| stage | `map` \| `mechanism` \| `constraint` \| `system` \| `synthesis` |
| loopRound | 本阶段第几轮循环 |
| claim | 一句关键结论（短） |
| epistemic | `fact` \| `inference` \| `hypothesis` \| `unknown` |
| summary | 2–5 句支撑摘要（不存全文） |
| citationIds | 引用 ID 列表 |
| falsifyIf | 证伪条件（可选） |
| supersedesId | 被哪条新证据取代（可选） |
| createdAt | ISO |

### 4.2 `citations` — 引用

| 字段 | 说明 |
|------|------|
| id | 主键 |
| url | 完整 URL |
| title | 页面/文档标题 |
| publisher | 来源机构（可选） |
| accessedAt | 访问日期 |
| excerpt | 关键原文一句（可选，≤280 字） |
| trustedSourceId | 若来自信源库，关联 ID（可选） |

### 4.3 `trusted_sources` — 优质信源库（人类策展）

| 字段 | 说明 |
|------|------|
| id | 主键 |
| pattern | 域名或 URL 模式，如 `*.hkexnews.hk` |
| label | 人类可读名称，如「港交所披露易」 |
| tags | `年报` `行业数据` `监管` `新闻` … |
| note | 为何优质、适用场景 |
| addedBy | `human` \| `ai_suggested` |
| companyId | 若仅适用于某标的，可填；空表示全局 |
| createdAt | ISO |

**人类典型动作**：某次调查中发现某站好用 →「加入信源库」；下次 AI Collect 时**优先推荐**库内 pattern。

### 4.4 `research_meta` — 调查元数据（每公司一条）

| 字段 | 说明 |
|------|------|
| companyId | 主键 |
| coreQuestions | 立项时 3 个待解问题 |
| currentStage | 当前 Tab |
| stageStatus | 各阶段 `locked` \| `active` \| `done` |

## 5. AI 在 Loop 中的职责边界

| 步骤 | AI 可做 | AI 不可做 |
|------|---------|-----------|
| 定向 | 根据阶段提出本轮子问题、列假设 | 替人类决定「调查结束」 |
| 收集 | 生成检索式、推荐 URL（含信源库优先）、结构化摘录草稿 | 编造未访问页面的数据 |
| 推敲 | 扮演挑剔同事：反证、逻辑漏洞、替代解释 | 附和人类明显薄弱推理 |
| 沉淀 | 起草 evidence 草稿供人类编辑后 Commit | 自动 Commit 且无引用 |

**输出格式建议**（便于入库）：

```markdown
【主张】……
【认知类型】fact | inference | hypothesis | unknown
【摘要】……
【引用】url1, url2
【证伪】若……则推翻
【建议加入信源库】url（理由一句）
```

## 6. 页面结构（Phase 2 示意）

**`/company/:id`**（仅 `investigating` 可进完整页）

```
┌──────────────────────────────────────────────────┐
│ 公司名 · 调查中          [信源库] [导出证据 JSON]   │
├────────┬─────────────────────────────────────────┤
│ Tab    │  本轮循环区                                │
│ 1–5    │  [定向][收集][推敲][沉淀]                  │
│        │  ─────────────────────────────────────   │
│        │  本阶段证据卡片列表（可修订/取代）          │
├────────┴─────────────────────────────────────────┤
│ 侧边：本阶段待解问题 · 优质信源快捷添加            │
└──────────────────────────────────────────────────┘
```

**`/sources`**（可选全局页）：浏览/编辑 `trusted_sources`。

## 7. 实现分期建议

| 阶段 | 范围 |
|------|------|
| **MVP（当前）** | 观察名单 + 开始调查 + 占位详情 |
| **2a** | 详情页 5 Tab 骨架 + 人工写 evidence（无 AI） |
| **2b** | citations + 证据卡片 CRUD + 推敲清单 UI |
| **2c** | 信源库 + 「从本页加入信源」 |
| **2d** | AI Loop（API Key 本地配置）+ Collect 推荐信源 |
| **3** | 后端代理检索（解决 CORS）、自动抓取摘要 |

---

## 8. 与「门外汉三步」的对照

| 直觉步骤 | Tab + Loop |
|----------|------------|
| 搜公司/行业 | Tab1 + 多轮 Collect/Commit |
| 供需与利润 | Tab2 |
| 本质/上下游/政治 | Tab3（约束）+ Tab4（系统）+ Tab5（总结） |

**关键增量**：Tab3 锁定生死线；全程 **证据卡片 + 引用**；**信源库**越用越顺手。
